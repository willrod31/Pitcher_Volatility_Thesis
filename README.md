# Valuing Pitcher Volatility: Identifying Asymmetric Upside for Low-Payroll Front Offices

Status: in progress. Data pipeline and Module 1 built. Modules 2-3 and dashboard scaffolded, not populated with real results yet.

## Problem

Large-market teams pay a premium for low-volatility, proven starters. Small-market teams can't afford that premium. This project builds a framework, using public Statcast data, to identify pitchers whose volatility is mispriced: elite raw pitch characteristics depressed by fixable factors like command or pitch usage, rather than inherent limitations.

## Deliverable

A Streamlit dashboard: select a team, select a player, get a generated report combining the three modules' output for that pitcher. Analysis and dashboard are both Python.

## Data note

Stuff+ and Location+ are proprietary (FanGraphs/PitcherList), not available via pybaseball or the public Statcast feed. This project builds its own Stuff+ Proxy from raw pitch physics (velocity, movement, spin, extension) regressed against outcome value, instead of relying on a black-box metric. See src/stuff_plus_proxy.py.

## Modules

Module 1 — Asymmetric Upside Index. Flags pitchers with elite Stuff+ Proxy but poor surface results explained by command, not shape. Index = z(Stuff+ Proxy) - z(Command Proxy). Also flags pitch-mix inefficiency: best-performing pitch type vs. most-used pitch type.

Module 2 — Volatility Discount Metric. Computes per-start variance in release point and velocity. Regresses future performance (next-start/30-day results) on current volatility to test whether volatility actually predicts decline, versus how much the market appears to penalize it.

Module 3 — Risk-Adjusted Value Projection. Combines Modules 1 and 2 into a projected WAR proxy, shrunk toward replacement level as volatility increases. Ranks pitchers by surplus value (risk-adjusted projected value minus contract cost).

## Setup

pip install -r requirements.txt
python -m src.data_acquisition   # pulls and caches a season of Statcast data

## Dashboard (before real data exists)

python dashboard/generate_sample_data.py
streamlit run dashboard/app.py

src/export_report_data.py is the hand-off point between analysis and dashboard: it joins Modules 1-3 output into one flat CSV with a fixed column contract. Swapping placeholder data for real output requires no changes to app.py.

## Known limitations

- Stuff+ Proxy is a linear regression on shape features, not a full replacement for proprietary gradient-boosted Stuff+ models.
- IL/injury history is not available via pybaseball — requires manual collection (Roster Resource/Spotrac) for any pitcher used in Module 2's predictive test.
- Contract cost data is not scriptable via pybaseball — requires manual collection for Module 3.
- simple_projected_war in Module 3 is an uncalibrated placeholder until regressed against actual historical WAR for a training sample.
